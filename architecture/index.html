architecture

Mich keeps task scheduling, memory ownership, IPC, capabilities, and hardware resource tracking in a small kernel core. Drivers run in isolated Ring 3 domains when isolation matters more than saving a context switch.

mich, not mach: capability-checked kernel handles and shared descriptor rings instead of copying every packet through microkernel IPC ports.

handles and objects

Hardware and kernel resources are exposed as typed objects (KOBJECT_*). Userspace never sees kernel pointers. Each process has a 32-slot handle table indexed by a 32-bit value: 

8-bit slot | 24-bit generation

Every handle carries explicit rights bits (KRIGHT_READ, KRIGHT_WRITE, KRIGHT_MAP, control, wait, signal, transfer). A 40,000-cycle test stresses slot reuse to make sure old handles stay dead after close.

userspace driver supervisor

The supervisor binds PCI devices to userspace capsules (like src/user64/virtio_net) using manifests and dependency checks.

When a driver stops or crashes, the supervisor sends a request to its Driver Bridge endpoint and gives it 32 ticks in STOPPING state to drain work and call stop-ack. Whether the driver answers or times out, teardown runs in a fixed order: mask IRQs and MSI-X vectors, clear PCI bus master, unmap MMIO and DMA pages, revoke handles, and run PCI Function Level Reset. If teardown fails, the device is quarantined and cannot be bound again.

iommu (intel vt-d and amd-vi)

DMA isolation lives in src/objects/iommu.c with backends for Intel VT-d (ACPI DMAR, root/context tables, second-level page tables, IOTLB flushes) and AMD-Vi (ACPI IVRS, device table entries, command ring, event log). When VT-d is present, coherent DMA buffers get bounded 16 MiB IOVA windows. Crash teardown strips those page-table entries before the driver process is reaped.

vfs, adytumfs v3, and the posix profile

The VFS stays in kernel space and uses the same object model (KOBJECT_VNODE, KOBJECT_DIRECTORY, KOBJECT_FILE, KOBJECT_MOUNT):

  • ramfs holds the root directory; boot modules mount read-only under /boot via bootfs
  • adytumfs v3 stores persistent trees, modes, and file data on block devices with CRC32C checksums
  • the static POSIX profile gives x86-64 ELF binaries standard calls (open, read, write, fork, execve, waitpid, poll, select, sockets, pledge, unveil, job control) without handing out CAP_VFS_ADMIN or raw hardware handles

network stack and netbench

Packets live in preallocated page pools. Each buffer ID carries a generation counter and one owner state at a time: 

FREE -> RX -> STACK -> TX -> TX_QUEUED -> DRIVER_RX / DRIVER_TX

The hot path never allocates pages or kernel objects. Below are single-CPU KVM rdtsc min cycle counts per packet on an Intel Core i3-7100U at 2.40GHz (512 warmup packets, 4096 sampled packets on vnic):

Direction 64 B 512 B 1500 B
RX 224 254 328
TX 296 758 1746
Echo 460 958 2024
